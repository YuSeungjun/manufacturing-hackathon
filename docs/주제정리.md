# 안전한 하루 — TBM 연계형 AI 안전이행 관리 시스템

제철소의 작업 전 안전점검회의(TBM)를 디지털로 기록하고, 그 자리에서 약속한 안전수칙을 AI가 현장 영상으로 확인해 안전관리자의 판단을 돕는 서비스.

> **한 줄 정의**
> 적어놓고 끝나던 TBM을, 지켜졌는지까지 확인되는 TBM으로.

---

## 1. 문제

### 현장에서 확인한 것

팀원 중 제철소 현장에서 **9년간 일한 경험자**가 있고, 그 사람이 전한 실태가 출발점이다.

- TBM을 **수기로 작성**한다.
- 주로 오늘 할 작업, 위험 요인, 해결 방안 5개 정도를 적는다.
- 그런데 **제대로 지켜지지 않는다.**

### 왜 안 지켜지나

| 단계 | 현재 | 문제 |
|---|---|---|
| 작성 | 종이에 손으로 | 작성 자체가 형식이 되기 쉽다 |
| 공유 | 구두 전달 | 누가 들었는지 남지 않는다 |
| 이행 | 각자 알아서 | 확인할 방법이 없다 |
| 사후 | 종이 보관 | 사고가 나야 들춰본다 |

핵심은 **작성과 이행 사이가 끊겨 있다**는 점이다. 아무리 잘 적어도 지켜졌는지 확인할 수단이 없으면 문서 작업으로 끝난다.

### 왜 지금인가

중대재해처벌법이 요구하는 건 안전보건관리체계 구축과 **그 이행 여부의 증빙**이다. 수기 TBM은 "적었다"는 것만 증명하고 "지켜졌다"는 건 증명하지 못한다.

```
TBM 작성 기록 + 작업자 서명 + AI 탐지 + 관리자 판단 이력
= 안전보건 조치를 실제로 했다는 증거
```

---

## 2. 솔루션

### 전체 흐름

```text
안전관리자: TBM 작성
  (위험 요인 + 안전 대책, 보호구 항목은 "AI 확인"으로 지정)
        ↓
작업자: 오늘의 TBM 확인 → 안전수칙 확인 서명
        ↓
현장 CCTV 이미지 → YOLOv8 PPE 모델 추론
        ↓
TBM 안전수칙과 매칭되는 위반 의심 항목만 "검토 대기" 등록
        ↓
안전관리자: 근거 이미지 + 탐지 박스 확인
        → 위반 확정 / 오탐 / 판단 보류
        ↓
확정된 건만 안전이행 점수에 반영 → 작업자에게 알림
```

### 핵심 원칙

> **AI는 탐지를 지원하고, 권한을 가진 사람이 최종 판단한다.**

AI 탐지만으로는 감점되지 않는다. 안전관리자가 위반으로 확정한 건만 점수에 반영된다. 이 구조가 오탐 리스크와 현장 수용성 문제를 동시에 해결한다.

---

## 3. 차별점

### 일반 PPE 모니터링과 무엇이 다른가

| | 일반 AI 안전관제 | 안전한 하루 |
|---|---|---|
| 탐지 기준 | 사업장 공통 규칙 | **그날 그 작업조가 적은 TBM 수칙** |
| 결과 | "안전모 미착용 감지" | "TBM 1번 수칙 위반 의심" |
| 판단 | 자동 알림 | 관리자가 근거 보고 확정 |
| 남는 것 | 탐지 로그 | 작성 → 서명 → 탐지 → 판단 전체 이력 |

같은 안전모 미착용이라도, **오늘 그 작업조가 스스로 적고 서명까지 한 수칙**을 어긴 것과 그냥 규정 위반인 것은 무게가 다르다. TBM과 탐지를 묶는 구조는 시중 제품에 잘 없다.

### 왜 TBM인가

TBM은 이미 법적으로도 관행적으로도 **매일 하는 일**이다. 새 프로세스를 만드는 게 아니라 이미 하는 걸 디지털로 옮기는 것이라 도입 저항이 작다.

---

## 4. 역할과 권한

가입할 때 역할을 선택하되, **안전관리자 권한은 가입만으로 주지 않는다.** 사업장 인증번호가 맞으면 즉시 승인, 모르면 승인 대기 상태로 두고 기존 안전관리자가 승인한다.

| 기능 | 작업자 | 안전관리자 |
|---|:--:|:--:|
| 본인 작업조 TBM 확인·서명 | O | O |
| 본인 관련 안전 알림 확인 | O | O |
| TBM 생성 | X | O |
| 전체 작업구역 현황 조회 | X | O |
| AI 탐지 결과 확인 | 본인 조만 | 전체 |
| 위반 확정 / 오탐 판단 | X | O |
| 안전관리자 가입 승인 | X | O |

화면에서 버튼을 숨기는 것과 별개로, **서버에서도 매 요청마다 역할을 검사**한다. 작업자 토큰으로 위반 확정을 요청하면 403으로 막힌다.

## 5. 화면 구성

### 작업자

- 오늘의 작업과 TBM 안전수칙
- 안전수칙 확인 서명 버튼
- 우리 조 오늘 안전이행 점수
- 나의 안전 알림 (확정 위반 / 오탐 / 검토 대기)

### 안전관리자

- 오늘의 안전 현황 대시보드 (TBM 수, 서명률, 검토 대기, 확정 위반)
- 작업구역별 안전이행 점수 표
- **AI 탐지 검토** — 근거 이미지 위에 탐지 박스 + 비교 대상 TBM 수칙을 나란히 표시
- **현장 영상 분석** — CCTV 캡처 업로드 → 추론
- **TBM 작성** — 위험 요인 / 안전 대책 / 위험도 / AI 확인 여부
- 안전관리자 가입 승인

## 6. 기술 구성

| 영역 | 사용 기술 |
|---|---|
| 웹 | Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS |
| DB | SQLite + Prisma 7 |
| 인증 | JWT 세션 쿠키(jose) + bcrypt |
| AI 서비스 | FastAPI + Ultralytics YOLOv8 |
| 모델 | `Hansung-Cho/yolov8-ppe-detection` (MIT) |

### AI 모델

클래스 10개: `Hardhat`, `NO-Hardhat`, `Mask`, `NO-Mask`, `Safety Vest`, `NO-Safety Vest`, `Person`, `Safety Cone`, `machinery`, `vehicle`

`NO-*` 클래스만 위반 의심으로 다루고, 내부 코드(`NO_HARDHAT` 등)로 변환해 TBM 안전수칙의 `ppeCode`와 매칭한다. 실제 샘플에서 안전모 미착용 88%, 안전조끼 미착용 81%, 방진마스크 미착용 62%로 탐지됐다.

### 데이터 모델

```text
User        — 사번, 역할(WORKER | SAFETY_MANAGER), 승인 상태, 소속, 작업조
Workplace   — 사업장, 안전관리자 인증번호
Team        — 작업조, 작업구역
Tbm         — 작업일, 작업 내용, 작업구역, 작성자, 배정 작업조
SafetyRule  — 위험 요인, 안전 대책, 탐지 방식, ppeCode, 위험도, 감점
TbmAck      — 작업자 확인 서명
Detection   — AI가 만든 위반 "의심" (근거 이미지, 박스, 신뢰도, 상태)
Review      — 사람이 내린 "판단" (확정 / 오탐 / 보류, 의견)
```

**Detection(AI의 의심)과 Review(사람의 판단)를 분리한 것이 설계의 핵심.** 안전이행 점수는 확정된 건만 감점한다.

## 7. 구현 현황

MVP 전 구간 동작 확인 완료 (브라우저 자동화로 11단계 검증).

- [x] 회원가입 (역할 선택 + 안전관리자 승인 절차)
- [x] 로그인 / 역할별 화면 분기 / 서버단 권한 검사
- [x] TBM 작성 및 작업조 배정
- [x] 작업자 TBM 확인 서명
- [x] 실제 YOLOv8 모델 추론 (목 데이터 아님)
- [x] TBM 수칙 ↔ 탐지 결과 자동 매칭
- [x] 근거 이미지 + 탐지 박스 오버레이
- [x] 위반 확정 / 오탐 / 보류 판단
- [x] 확정 건만 반영되는 안전이행 점수
- [x] 작업구역별 현황 대시보드

### 아직 안 한 것

- 실시간 CCTV 스트림 연동 (현재는 캡처 이미지 업로드 방식)
- 모바일 화면 최적화
- 통계 기간 조회 (현재는 당일 기준)

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| AI 오탐으로 작업자가 억울하게 감점 | 확정 판단은 사람만. 오탐 버튼을 1순위로 배치 |
| 감시 도구로 인식되어 현장 반발 | 개인이 아닌 **작업구역·작업조 단위** 탐지. 점수는 조 단위 |
| 개인정보 문제 | 얼굴 인식 미사용. 안전모·마스크 착용 환경에서 정확도 확보도 어려움 |
| 제철소 CCTV 데이터 부재 | 공개 PPE 데이터셋 이미지로 데모, 실제 연동은 API 한 곳만 바꾸면 됨 |
| 관리자 업무 부담 증가 | TBM 수칙과 매칭되는 항목만 검토 대기로 올림 |

---

## 9. 확장 방향

1. **실시간 스트림** — CCTV 프레임을 주기적으로 뽑아 동일 API로 전달
2. **탐지 항목 확대** — 방열복, 보안면, 안전대, 출입 금지 구역 침입
3. **센서 연동** — 가스검지기, LOTO 시건 상태
4. **누적 통계** — 작업구역·기간별 안전이행 추이, 반복 위반 유형 분석
5. **TBM 추천** — 과거 위반 이력을 반영해 오늘 작업의 위험 요인 초안 제시

## 10. 데모 시나리오

1. 안전관리자 `M0001` 로그인 → 오늘의 안전 현황
2. **현장 영상 분석** → 샘플 이미지 업로드 (임계값 0.25)
   → 안전모·안전조끼·방진마스크 미착용 3건이 검토 대기로 등록
3. **AI 탐지 검토** → 근거 이미지의 탐지 박스와 TBM 수칙을 비교
   → 1건 `위반 확정`, 1건 `오탐`
4. 작업조 안전이행 점수 100 → 90 반영
5. 작업자 `W1002` 로그인 → TBM 서명, 확정된 위반 알림 확인
6. 작업자가 관리자 화면 직접 접근 시도 → 403 차단
