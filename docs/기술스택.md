# 사용 기술

압연설비 위험구역 감시 서비스의 기술 구성. 2026-08-24 기준 실제 코드에 들어 있는 것만 적었다.

---

## 전체 구조

```text
브라우저
  │  영상 업로드는 Vercel Function 본문 4.5MB 제한을 피해
  │  Vercel Blob 으로 직접 올린다
  ↓
Next.js (Vercel)  ──── Neon Postgres
  │                     설비 / 구역 / 작업 / 분석 / 위험사건
  │  videoUrl 만 전달
  ↓
FastAPI (Hugging Face Space, Docker)
  │
  ├─ YOLO26n        사람 검출
  ├─ ByteTrack      프레임 간 동일인 연결
  ├─ CLIP ViT-B/32  안전대 착용 · 훅 체결 판정
  └─ risk.py        위험 판정 상태머신 (모델 아님)
```

## 1. AI 서비스

### 모델

| 모델 | 역할 | 위치 |
|---|---|---|
| **YOLO26n** | 사람 검출. COCO `person` 클래스 하나만 사용 | `ai/models/yolo26n.pt` |
| **ByteTrack** | 다중 객체 추적. 프레임 간 동일인 연결 | Ultralytics 내장 + `ai/trackers/pinch_bytetrack.yaml` |
| **CLIP ViT-B/32** | 안전대 착용 · 훅 체결 제로샷 판정 | `weights/clip/ViT-B-32.pt` |
| **Roboflow 호스팅 추론** | 안전대 판정 1순위 공급자 (외부 API) | `detect.roboflow.com` |

안전대 판정 공급자는 `auto`일 때 **Roboflow → CLIP → 로컬 가중치** 순으로 있는 것을 쓰고,
`HARNESS_PROVIDER` 로 고정할 수 있다. 어느 쪽으로 판정했는지는 `/health` 응답과 화면에
그대로 밝힌다 — 남의 학습 결과를 우리 것으로 읽히게 두지 않기 위해서다.

### CLIP 을 쓴 이유

안전대는 학습 데이터를 구하기 어렵다. YOLO-World 로 "safety harness" 를 물체로 찾으려는
시도는 **신뢰도 0.02** 에 그쳤다 (`yolov8s-worldv2.pt`, 실측).

사람 위치는 이미 YOLO 가 잡아 주므로 남는 문제는 **분류 하나**뿐이고, 분류는 탐지보다
훨씬 쉽다. 그래서 상체 crop 을 문장 두 개와 비교하는 제로샷 방식으로 바꿨다.

```text
"a worker with black safety harness straps across the back and shoulders"
"a worker wearing only a plain work jacket"
```

부정 프롬프트에 **없음을 쓰면 안 된다**는 것이 실측으로 갈렸다.

| 부정 프롬프트 | 미착용자 판정 |
|---|---|
| `no straps on the back` | UNKNOWN (0.46) — 흘림 |
| `nothing attached to it` | WORN (0.79) — **틀림** |
| `only a plain work jacket` | 0.16 — 착용자 1.00 과 갈림 |

CLIP 은 부재를 보지 못한다. 보이는 것을 묘사해야 한다.

### 판정은 모델이 아니라 규칙

모델은 "사람이 어디 있나"까지만 답한다. 위험 판정은 상태머신(`ai/risk.py`)이 한다.

| 코드 | 뜻 |
|---|---|
| `ZONE_INTRUSION` | 위험구역 진입 |
| `PROLONGED_DWELL` | 위험구역 잔류 |
| `LOTO_MISSING` | 시건 없이 작업 |
| `ENTRY_WHILE_RUNNING` | 가동 중 위험구역 진입 |
| `RESTART_WITH_WORKER_INSIDE` | 작업자 잔류 중 재가동 |

끼임은 "사람이 들어간 사건"이 아니라 **사람이 안에 있는 채로 설비가 깨어난 사건**이다.
그래서 설비 상태 타임라인(`machineStates`)이 없으면 CRITICAL 이 성립하지 않는다.
타임라인을 안 주면 `STOPPED` 로 가정하고 진입·잔류만 낸다 — 안전한 기본값이다.

구역 판정에는 비대칭 2-임계(`ENTER 0.60` / `EXIT 0.25`)와 N-of-M 연속 프레임 투표를 쓴다.
진입은 빠르게, 이탈은 느리게 잡기 위해서다.

### 데이터 모델 (16개)

```text
Workplace · Team · User                       조직과 권한
Equipment · DangerZone · CameraFeed           설비와 위험구역
MaintenanceWork · WorkAssignee · LotoLock     정비 작업과 시건
VideoAnalysis · RiskEvent · Review            분석과 사람의 판단
```

`RiskEvent`(AI 가 만든 근거)와 `Review`(사람이 내린 판단)를 분리한 것이 설계의 축이다.

## 3. 배포

| 대상 | 플랫폼 | 비고 |
|---|---|---|
| 웹 | Vercel | 서버리스 함수, Blob 스토리지 |
| AI | Hugging Face Space | Docker SDK, 포트 8000 |
| DB | Neon (Vercel 마켓플레이스) | 로컬·배포가 같은 DB 를 본다 |

### 컨테이너에서 겪은 것

- **PyTorch 는 CPU 휠로 따로 받는다.** 기본 인덱스는 CUDA 런타임까지 끌고 와 이미지가 3GB 를 넘는다.
- **스레드를 2로 고정한다.** 2 vCPU 환경에서 호스트 코어 수대로 8~16 스레드를 띄우면 오히려 2~3배 느려진다.
- **가중치를 빌드 때 받아 둔다.** 콜드 스타트에 받으면 첫 요청이 30초를 넘는다.
- **`--workers 1` 필수.** 추적기 상태와 잡 레지스트리가 프로세스 메모리에 있어, 워커가 둘이면 서로의 track id 를 오염시킨다.
- **비동기 잡 + 폴링.** HF Space 게이트웨이 타임아웃(~60초)과 업로드 시간을 한꺼번에 우회한다. 부수효과로 진행률 바가 생겼다.
- **서버 타임존을 못 박는다.** Vercel 함수는 기본이 UTC 라 "오늘"이 9시간 어긋난다.

## 5. 개인정보

| 항목 | 처리 |
|---|---|
| 얼굴 인식 | 하지 않음 |
| 개인 식별 | 하지 않음. COCO `person` 클래스 하나만 본다 |
| track id | 한 영상 안에서만 쓰는 익명 번호. 분석이 끝나면 사라진다 |
| 저장 캡처 | bbox 상단 28%(머리)를 가우시안 블러 처리 |

이 선언은 문서에만 있는 게 아니라 `GET /health` 응답에
`identifiesIndividuals: false`, `faceBlur: true` 로 박혀 있다.
